# flex-able · 텅장관리

고정지출과 앞으로의 약속을 미리 빼두고, **오늘 더 쓸 수 있는 생활비**를 알려주는 모바일 웹앱입니다. 계정이나 서버 없이 현재 브라우저에 저장하는 버전입니다.

## 실행

Node.js 24 이상을 사용합니다.

```sh
npm ci
npm run dev
```

`http://localhost:5173`에서 실행됩니다. 같은 Wi-Fi의 휴대폰에서는 개발 서버가 표시한 네트워크 주소로 접속할 수 있습니다. 시스템 알림과 홈 화면 설치 등 일부 기능에는 HTTPS 또는 localhost가 필요합니다.

```sh
npm test             # 예산 계산과 입력 검증
npm run build        # 타입 검사, 빌드, 오프라인 앱 셸 생성
npm run preview      # 빌드한 앱 실행
npx playwright install chromium
npm run test:e2e     # 모바일 브라우저 사용자 흐름
```

GitHub Actions에서도 계산 테스트, 빌드, 모바일 브라우저 테스트를 수행합니다.

## 계산 원칙

계산 구간은 **오늘부터 다음 실제 수입일 전날**까지입니다. 다음 수입 예정액은 현재 예산에 더하지 않습니다.

```text
현재 남은 일반 생활비
  = 현재 잔액
  - 미납 고정지출의 남은 확보액
  - 미결제 카드 이용액 (카드 크레딧은 사용 가능액에 더하지 않음)
  - 보호할 저축·비상금
  - 이번 구간의 확정된 계획 잔여 확보액

오늘 시작 기준액
  = max(0, floor((현재 남은 일반 생활비 + 오늘 일반 소비 순액) / 남은 날짜 수))

오늘 더 쓸 수 있는 금액
  = max(0, 오늘 시작 기준액 - 오늘 일반 소비 순액)
```

현재 잔액에는 오늘 실제 소비가 이미 반영되었으므로, 시작 기준액을 구할 때만 오늘 일반 소비를 되돌립니다. 계획 소비·고정지출은 일반 소비 순액에서 제외합니다. 날짜가 바뀌면 오늘 순액이 0이 되어 남은 예산을 남은 일수에 재분배합니다.

- **계획과 실제 결제:** 거래에서 계획을 선택합니다. 부분 결제는 잔여 확보액만 줄이고, ‘정산 완료’를 선택하면 남은 확보액을 해제합니다. 8만 원을 확보하고 7만 원을 쓰면 1만 원이 생활비로 돌아갑니다.
- **신용카드:** 사용 시 계좌 잔액 대신 미결제액을 늘립니다. 납부 시 계좌 잔액과 미결제액을 동시에 줄여 이중 차감을 방지합니다.
- **환불:** 원래 지출과 연결하고 결제 방법·계획 연결을 계승합니다. 누적 환불액은 원거래액을 넘을 수 없습니다.
- **이체:** 등록한 자금 내부 이동으로 기록하고 총 잔액과 소비에는 반영하지 않습니다.
- **부족:** 음수 생활비는 0원과 부족액을 함께 표시합니다. 당일 초과액과 전체 구간 부족액을 구분합니다.
- **미정산:** 추적 시작 이후 누락된 날짜와 미확인 과거 거래 날짜가 남아 있으면 잠정 금액입니다. 무지출도 사용자가 확인해야 합니다.
- **수입 구간 갱신:** 실제 수입 거래를 등록한 뒤 설정에서 다음 수입일과 새 구간 고정지출을 확인합니다. 날짜만 됐다고 예정 수입을 입금 처리하지 않습니다.
- **반복 항목:** 고정지출은 구간별 명시적 납부 항목입니다. 보호 금액의 매주·매달 주기는 참고 메모이며, 자동으로 반복 차감하지 않습니다.

## 실제 동작과 연결이 필요한 기능

| 기능           | 현재 상태                                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 금융 데이터    | 토스·카카오페이·오픈뱅킹 연결 없음. 직접 입력, 캡처, 명시적인 예시 내역 시연 제공                                            |
| 캡처 OCR       | Tesseract.js `kor+eng`를 브라우저 안에서 실행. 첫 실행 시 인식 엔진·언어 데이터 다운로드 필요. 이미지 자체는 업로드하지 않음 |
| 자연어 계획    | 기기 내 규칙 기반 날짜·금액·카테고리 추출. 생성형 AI 또는 외부 시세 추론 없음                                                |
| 개인화 금액    | 같은 카테고리에서 정산된 계획의 실제 비용 범위·평균을 사용. 기록이 없으면 직접 입력 요청                                     |
| 소비 기준 메모 | 계획 입력 화면에서 참고할 수 있는 로컬 메모. AI에 자동 학습시키거나 예산을 임의 변경하지 않음                                |
| 캘린더         | `.ics` 파일 불러오기. 계정 연결·실시간 동기화 없음. 반복 규칙은 펼치지 않고 명시된 시작일만 가져옴                           |
| 알림           | 앱이 열려 있을 때 정산 시간 알림과 권한이 허용된 시스템 알림. 앱을 닫은 상태의 백그라운드 푸시 없음                          |
| 오프라인       | 배포용 앱 셸을 최초 캐시한 후 일반 기록·계산·계획 이용 가능. 첫 OCR 실행은 온라인 필요                                       |
| 저장           | 브라우저 localStorage, 수동 백업·복원. 서버 저장·여러 기기 동기화·로그인 없음                                                |

원본 캡처는 화면 안의 일시적인 URL과 메모리로만 취급하고, 닫으면 해제합니다. 보관하는 것은 사용자가 확인한 거래 정보입니다. 인식이 불확실하거나 거래 구분이 다르면 저장 전에 수정해야 합니다. 환불·카드 납부는 직접 입력에서 원거래와 미결제액을 확인합니다.

기기 데이터를 삭제하면 기록도 삭제됩니다. 백업 파일에는 거래 내역이 포함되므로 사용자가 직접 관리해야 합니다. 저장소 오류가 나면 저장 완료로 표시하지 않습니다. 형식이 손상된 기존 데이터는 자동 덮어쓰기 없이 복구 화면에서 원본을 내려받을 수 있습니다.

## 확인한 핵심 시나리오

- 30만 원 / 10일 = 하루 3만 원 → 계획 8만 원 확정 → 하루 22,000원.
- 일반 소비 1만 원 기록 → 오늘 남은 생활비 12,000원, 기준액은 22,000원 유지.
- 계획 실제 비용 7만 원으로 완료 → 1만 원 반환. 부분 결제·초과 소비·취소도 검증.
- 카드 소비와 카드 납부의 중복 차감 방지, 환불 한도, 삭제 복원, 수입일 경계, 미정산 상태 검증.
- 한글 거래 캡처 두 건 인식과 중복 의심 후보 제외를 실제 브라우저에서 확인.

## 기술 구성

- React + TypeScript + Vite
- Lucide 아이콘, Pretendard Variable
- Tesseract.js 기기 내 OCR (필요한 화면에서 지연 로드)
- 순수 계산 함수와 Vitest 회귀 테스트
- Playwright 모바일 사용자 흐름 테스트
- Web App Manifest + Service Worker

`src/domain.ts`가 예산 계산과 거래 처리, `src/forms.tsx`가 입력·캡처, `src/App.tsx`가 화면·저장 흐름을 담당합니다. 실제 AI·금융 API를 연결할 때도 금액 산술과 최종 확인은 이 계산 모듈과 사용자에게 남겨둡니다.

빌드 결과 `dist/`를 HTTPS 정적 호스팅의 루트 경로에 배포할 수 있습니다. 현재 자산 경로와 서비스 워커 범위는 `/` 기준이므로 저장소 하위 경로 방식의 GitHub Pages를 사용하려면 base와 서비스 워커 경로를 조정해야 합니다. GitHub 업로드 자체가 서비스 배포를 의미하지는 않습니다.

폰트 라이선스는 `public/fonts/LICENSE.txt`에 포함했습니다.

# flex-able · 텅장관리

고정지출과 앞으로의 약속을 미리 빼두고, **오늘 더 쓸 수 있는 생활비**를 알려주는 모바일 앱입니다. React 프론트, Spring Boot 백엔드, MySQL로 구성된 3-Tier 구조이며 예산 규칙과 데이터의 기준은 서버입니다.

```text
React + Vite (루트)  ──REST/JSON──▶  Spring Boot (backend/)  ──JDBC──▶  MySQL
```

설계와 단계별 진행은 [docs/architecture.md](docs/architecture.md)에 있습니다.

## 실행

Node.js 24, Java 21, Docker가 필요합니다. 세 구성요소는 **따로 실행할 수 있고 어떤 순서로 띄워도 됩니다.**

```sh
npm ci
docker compose up -d db               # MySQL 8.4 (localhost:3306)
cd backend && ./gradlew bootRun       # API (localhost:8080)
npm run dev                           # 앱 (localhost:5173)
```

전체를 컨테이너로 띄울 수도 있습니다 (앱 `localhost:3000`).

```sh
docker compose up
```

- DB가 없으면 백엔드는 떠 있지만 `/actuator/health/readiness`가 DOWN이고, API는 `503`과 `Retry-After`를 돌려줍니다. DB가 준비되면 재시작 없이 정상화됩니다.
- 백엔드가 없으면 앱은 "서버에 연결할 수 없어요" 화면과 다시 연결 버튼을 보여줍니다. 연결이 끊기면 마지막으로 불러온 금액을 보여주며 다시 시도할 수 있습니다.
- 앱이 호출할 API 주소는 배포 시 `API_BASE_URL`(컨테이너가 `/config.json`으로 주입)이나 빌드 시 `VITE_API_BASE_URL`로 정합니다. 둘 다 없으면 같은 호스트의 8080 포트를 씁니다.
- 백엔드 설정은 환경변수(`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `CORS_ALLOWED_ORIGINS`, `SERVER_PORT`, `AUTH_JWT_SECRET`)로 바꿉니다. compose용 값은 `.env.example`에 있습니다.
- 운영에서는 `AUTH_JWT_SECRET`(`openssl rand -base64 32`)을 반드시 지정해야 합니다. 비우면 재시작할 때마다 모두 로그아웃됩니다.

```sh
npm test                              # 입력 보조 · API 공통 계층
cd backend && ./gradlew test          # 예산 규칙 · API · DB 장애 복구 (Testcontainers, Docker 필요)
npx playwright install chromium
npm run test:e2e                      # 실제 백엔드 · MySQL과 모바일 브라우저 흐름
```

E2E는 Playwright가 MySQL(13306, docker compose 별도 프로젝트), 백엔드(18080), 앱(5173)을 직접 띄웁니다. GitHub Actions에서도 세 테스트를 모두 실행합니다.

## 계산 원칙

계산 구간은 **오늘부터 다음 실제 수입일 전날**까지입니다. 다음 수입 예정액은 현재 예산에 더하지 않습니다.

```text
현재 남은 일반 생활비
  = 현재 잔액
  - 미납 고정지출의 남은 확보액
  - 미결제 카드 이용액 (카드 크레딧은 사용 가능액에 더하지 않음)
  - 보호할 저축·비상금
  - 이번 구간의 확정된 계획 잔여 확보액

오늘 시작 기준액
  = max(0, floor((현재 남은 일반 생활비 + 오늘 일반 소비 순액) / 남은 날짜 수))

오늘 더 쓸 수 있는 금액
  = max(0, 오늘 시작 기준액 - 오늘 일반 소비 순액)
```

현재 잔액에는 오늘 실제 소비가 이미 반영되었으므로, 시작 기준액을 구할 때만 오늘 일반 소비를 되돌립니다. 계획 소비·고정지출은 일반 소비 순액에서 제외합니다. 날짜가 바뀌면 오늘 순액이 0이 되어 남은 예산을 남은 일수에 재분배합니다.

- **계획과 실제 결제:** 거래에서 계획을 선택합니다. 부분 결제는 잔여 확보액만 줄이고, ‘정산 완료’를 선택하면 남은 확보액을 해제합니다. 8만 원을 확보하고 7만 원을 쓰면 1만 원이 생활비로 돌아갑니다.
- **신용카드:** 사용 시 계좌 잔액 대신 미결제액을 늘립니다. 납부 시 계좌 잔액과 미결제액을 동시에 줄여 이중 차감을 방지합니다.
- **환불:** 원래 지출과 연결하고 결제 방법·계획 연결을 계승합니다. 누적 환불액은 원거래액을 넘을 수 없습니다.
- **이체:** 등록한 자금 내부 이동으로 기록하고 총 잔액과 소비에는 반영하지 않습니다.
- **부족:** 음수 생활비는 0원과 부족액을 함께 표시합니다. 당일 초과액과 전체 구간 부족액을 구분합니다.
- **미정산:** 추적 시작 이후 누락된 날짜와 미확인 과거 거래 날짜가 남아 있으면 잠정 금액입니다. 무지출도 사용자가 확인해야 합니다.
- **수입 구간 갱신:** 실제 수입 거래를 등록한 뒤 설정에서 다음 수입일과 새 구간 고정지출을 확인합니다. 날짜만 됐다고 예정 수입을 입금 처리하지 않습니다.
- **반복 항목:** 고정지출은 구간별 명시적 납부 항목입니다. 보호 금액의 매주·매달 주기는 참고 메모이며, 자동으로 반복 차감하지 않습니다.

## 같은 결제를 두 번 넣지 않기

캡처 · CSV · 직접 입력으로 이미 등록된 결제와 같아 보이는 거래를 추가하면 막지 않고 **"이미 있는 거래 같아요. 그래도 추가할까요?"**라고 묻습니다. 판정은 서버가 합니다.

- 같은 날짜 · 금액 · 이름이면 확실한 중복, 같은 날 같은 금액이거나 하루 차이(승인일/매입일)에 이름이 비슷하면 중복 의심입니다. "스타벅스코리아"와 "스타벅스 강남점"처럼 표기가 달라도 찾습니다.
- 가져오기 확정 요청에 사용자가 확인하지 않은 중복이 있으면 서버가 거절하고 해당 항목을 알려줍니다.
- 같은 요청을 다시 보내거나 같은 외부 이벤트(결제 알림 등)가 다시 들어와도 한 번만 반영됩니다.

## 현재 범위

| 기능        | 상태                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| 계정        | 이메일 · 비밀번호, 게스트 둘러보기. 웹은 Refresh Token을 HttpOnly 쿠키로만 다루고 Access Token은 메모리에만 둠        |
| 캡처 OCR    | Tesseract.js `kor+eng`를 브라우저에서 실행. 이미지는 업로드하지 않고, 인식한 문자로 서버가 후보를 만든다              |
| CSV         | 엑셀에서 저장한 CSV(UTF-8, EUC-KR). 은행 · 카드사 머리행 자동 판별, 열 직접 지정 가능. `.xlsx`는 CSV로 저장 후 업로드 |
| 계좌 연동   | 미연결. 마이데이터는 허가 사업자만 직접 호출할 수 있어 서버가 중계 API를 호출하는 방식으로 준비 중                    |
| 자연어 계획 | 기기 내 규칙 기반 날짜 · 금액 · 카테고리 추출. 생성형 AI 없음. 저장 전 사용자가 확인                                  |
| 캘린더      | `.ics` 파일 불러오기. Google · Android 캘린더 연동은 Android 앱 단계에서 추가                                         |
| 알림        | 앱이 열려 있을 때 정산 시간 알림. 결제 알림 자동 등록은 Android 앱 단계에서 추가                                      |
| 오프라인    | 앱 화면은 캐시되지만 데이터 조회 · 변경에는 서버 연결이 필요                                                          |

원본 캡처는 화면 안의 일시적인 URL과 메모리로만 취급하고, 닫으면 해제합니다. 저장하는 것은 사용자가 확인한 거래 정보입니다.

## 기술 구성

- 프론트: React + TypeScript + Vite, Lucide 아이콘, Pretendard, Tesseract.js, Web App Manifest + Service Worker
  - `src/api/`: 모든 서버 호출이 거치는 공통 계층 (주소 결정, 타임아웃, 오류 형식, 연결 상태, 토큰 갱신)
  - `src/App.tsx` 화면 · 흐름, `src/forms.tsx` 입력, `src/importUI.tsx` 가져오기, `src/domain.ts` 타입 · 표시 유틸 · 입력 보조
- 백엔드: Spring Boot 4.1, Java 21, Spring Security(JWT), JPA, Flyway, Actuator. 예산 규칙은 `backend/.../ledger/domain/Ledger`
- 테스트: Vitest, JUnit + Testcontainers(MySQL), Playwright(실제 백엔드)

폰트 라이선스는 `public/fonts/LICENSE.txt`에 포함했습니다.
